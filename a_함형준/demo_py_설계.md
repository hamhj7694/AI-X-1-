# 보이스피싱 탐지 서비스 `demo.py` 설계

## 요약

사용자가 새로운 통화 텍스트를 입력하면 동일한 특징 추출기를 적용해 **Window 모델의 구간별 위험점수**와 **Case 모델의 종합 위험점수**를 계산하고, 위험 판단과 근거 문구를 함께 보여주는 Streamlit 데모를 구현한다.

- Window 모델: 최근 10개 발화를 5개 발화씩 이동하며 실시간 위험 변화를 탐지
- Case 모델: 전체 입력 특징과 Window 점수 흐름을 결합해 종합 판단
- 위험점수: `보정확률 × 100`
- 기존 운영 기준: Window 69점, Case 58점
- 최종 종합점수: 별도 평균값이 아니라 **Case 위험점수**를 사용
- 최종 결론: Window 즉시경고와 Case 종합판정을 함께 적용
- 결과 설명: 탐지 변수, 근거 문구, 구간 위치, 모델 기여도를 제공

> 이 점수는 현재 내부 데이터 분포에서 보정한 위험점수다. 외부 검증이 끝나기 전에는 실제 보이스피싱 발생확률이나 금융기관의 확정 판정으로 표현하지 않는다.

## 1. 구현 목적

다음 흐름을 한 화면에서 시연한다.

```text
새 통화 텍스트 입력
→ 발화 분리·정규화
→ 위험 특징 추출
→ 10개 발화 Window 생성
→ Window 모델 구간별 점수 계산
→ Window 점수 요약 + 전체 특징 생성
→ Case 모델 종합 점수 계산
→ 위험 단계·판정·근거 표시
```

이 화면은 실제 송금 차단 기능이 아니라, 현재 구축한 ML 위험 탐지 방식을 설명하고 검증하는 프로토타입이다.

## 2. 현재 모델 점수 확인 결과

### 공통 점수식

```python
raw_probability = model.predict_proba(features)[:, 1]
calibrated_probability = calibrator(raw_probability)
risk_score = calibrated_probability * 100
```

| 구분 | 모델 | 보정 방식 | 역할 | 기존 기준 |
|---|---|---|---|---:|
| Window | Random Forest | Platt Calibration | 통화 중 구간별 조기경고 | 69점 |
| Case | Random Forest `STACKED_SAFE` | Identity | 전체 입력의 종합 보조판정 | 58점 |

### 총합 점수의 정의

현재 학습 결과에는 `Window 점수 × 가중치 + Case 점수 × 가중치` 형태의 별도 총합 공식이 없다.

Case 모델은 다음 정보를 이미 함께 학습한 종합 모델이다.

- 전체 통화에서 추출한 Case 특징 12개
- Window 보정확률 요약 8개
  - 평균, 최댓값, 90백분위수, 변동성
  - 최초값, 최종값, 증감량, 추세

따라서 데모 화면에서는 다음처럼 표시한다.

```text
구간 위험점수 = Window별 Risk Score
Window 대표점수 = Window Risk Score의 최댓값
최종 종합 위험점수 = Case Risk Score
```

임의의 산술평균을 새로 만들어 ‘ML 최종점수’라고 표시하지 않는다.

## 3. 최종 판정 정책

```python
window_alert = max_window_score >= 69
case_alert = case_score >= 58
```

| Window 판정 | Case 판정 | 화면 단계 | 안내 문구 |
|---|---|---|---|
| 기준 미만 | 기준 미만 | 관찰 | 현재 기준을 넘는 위험 신호가 확인되지 않음 |
| 기준 미만 | 58점 이상 | 의심 | 전체 문맥에서 보이스피싱 의심 신호가 확인됨 |
| 69점 이상 | 기준 미만 | 즉시 경고 | 특정 구간에서 강한 위험 신호가 확인됨 |
| 69점 이상 | 58점 이상 | 고위험 | 구간 탐지와 전체 문맥 판단이 모두 위험 기준을 넘음 |

주의사항:

- `관찰`은 정상 확정이 아니다.
- 4단계 명칭은 서비스 화면을 위한 운영 표현이며, 학습된 확률 구간이 아니다.
- Window 경고는 실시간 대응용이고 Case 결과는 전체 입력에 대한 종합 확인용이다.
- 입력 발화가 10개 미만이면 Window 점수를 만들지 않고 `분석 불충분`으로 표시한다.

## 4. 입력 화면

### 필수 입력

`st.text_area()`에 한 줄당 한 발화를 입력한다.

```text
범인: 서울중앙지검 수사관입니다.
피해자: 무슨 일이시죠?
범인: 고객님 명의 계좌가 범죄에 연루됐습니다.
범인: 지금 은행에 가서 현금을 인출하세요.
```

### 입력 규칙

- 한 줄을 1개 발화로 처리한다.
- `범인:`, `피해자:`, `상담원:` 등의 접두어가 있으면 역할 정보와 본문을 분리한다.
- 접두어가 없어도 분석은 가능하지만 화자 관련 특징은 제한될 수 있다.
- 빈 줄과 연속 공백을 제거하되 원문은 별도로 보존한다.
- 개인정보, 계좌번호, 전화번호는 화면 출력 전에 마스킹한다.
- 입력 내용은 기본적으로 파일이나 로그에 저장하지 않는다.

### 입력 보조 기능

- `예시 불러오기`: 정상상담형·대출사기형·수사기관사칭형 예시
- `분석하기`: 사용자가 눌렀을 때만 모델 실행
- `초기화`: 입력과 결과 삭제
- 입력 발화 수와 Window 생성 가능 여부 사전 표시

## 5. 모델 입력 특징

두 모델은 같은 의미 체계를 사용하되, Case는 전체 누적값을, Window는 직전 구간 대비 변화량을 사용한다.

| 한글 표시명 | 모델 변수 | 확인 내용 |
|---|---|---|
| 공공기관 사칭 | `imp_public` | 검찰·경찰·법원·금융감독원 등 사칭 신호 |
| 금융기관 사칭 | `imp_financial` | 은행·카드사·캐피탈·저축은행 등 사칭 신호 |
| 권위·신뢰 형성 | `strategy_authority` | 직책·사건번호·기관 권위를 이용한 신뢰 형성 |
| 공포·위협 | `strategy_fear` | 체포·구속·압류·범죄 연루 등 위협 표현 |
| 정보 추출 | `strategy_info_extraction_sem` | 상대방의 금융·개인정보를 알아내려는 표현 |
| 민감정보 요구 | `sensitive_info_request_sem` | 계좌·신분증·주민번호 등 요구 |
| 인증정보 요구 | `auth_info_request_sem` | 비밀번호·OTP·인증번호 등 요구 |
| 심리전략 다양성 | `strategy_diversity_sem` | 한 입력에서 함께 나타난 심리전략 종류 수 |
| 요구행동 다양성 | `action_diversity_sem` | 송금·인출·앱 설치 등 요구행동 종류 수 |
| 위험신호 계열 수 | `signal_family_count_sem` | Case 전체에서 확인된 위험신호 계열 수 |
| 위험신호 증가량 | `signal_family_count_delta_sem` | Window의 직전 구간 대비 위험신호 증가량 |
| 신분주장×권위 | `ix_identityclaim_authority_sem` | 신분·소속 주장과 권위 표현의 동시 출현 |
| 정보추출×민감정보 | `ix_info_sensitive_sem` | 정보 탐색과 민감정보 요구의 동시 출현 |

Case와 Window는 각각 12개를 사용하며 `signal_family_count_sem`과 `signal_family_count_delta_sem`이 서로 교체된다.

## 6. 결과 화면 구성

### 6.1 최상단 결과 요약

4개 KPI를 표시한다.

| KPI | 내용 |
|---|---|
| Window 최고 위험점수 | 모든 Window 중 가장 높은 점수와 발생 구간 |
| Case 종합 위험점수 | 전체 문맥과 Window 흐름을 결합한 최종 점수 |
| 최종 판정 | 관찰·의심·즉시 경고·고위험 |
| 모델 일치 여부 | 두 모델이 위험 기준에 대해 같은 결론인지 표시 |

점수 옆에는 항상 해당 임계값과 점수의 의미를 같이 표시한다.

```text
Window 74점 / 경고 기준 69점
Case 63점 / 의심 기준 58점
```

### 6.2 Window 위험 변화

- X축: 입력 발화 구간
- Y축: Window 위험점수 0~100
- 69점 경고선을 함께 표시
- 가장 위험한 Window를 강조
- 점을 선택하면 해당 구간의 원문과 탐지 근거를 표시

### 6.3 의심 근거 문구

입력 원문에서 탐지된 부분을 범주별 색으로 강조한다.

```text
[공공기관 사칭] 서울중앙지검 수사관입니다.
[공포·위협] 고객님 명의 계좌가 범죄에 연루됐습니다.
[현금 인출 요구] 지금 은행에 가서 현금을 인출하세요.
```

표현이 키워드 규칙에 걸렸다는 사실과 모델 판단에 실제로 기여했다는 사실은 구분한다.

### 6.4 탐지 변수 상세표

| 컬럼명 | 설명 |
|---|---|
| 구간 | 전체 또는 Window 번호·발화 범위 |
| 위험 범주 | 사칭·심리전략·요구행동·상호작용 |
| 한글 변수명 | 사용자가 읽는 변수 이름 |
| 모델 변수명 | 모델에 전달된 영문 컬럼명 |
| 추출값 | 0/1, 횟수, 비율 또는 변화량 |
| 근거 발화 | 해당 변수를 만든 원문 |
| 근거 표현 | 실제 탐지된 단어·구문 |
| Case 기여도 | Case 예측을 올리거나 내린 SHAP 값 |
| Window 기여도 | 최고위험 Window 예측의 SHAP 값 |
| 판정 방향 | 위험 증가·위험 감소·영향 작음 |
| 추출 방식 | RULE·SEMANTIC·INTERACTION |

### 6.5 모델 상세정보

접을 수 있는 영역에 다음을 표시한다.

- 원시 예측확률 `p_raw`
- 보정확률 `p_cal`
- 위험점수 `p_cal × 100`
- 적용 임계값과 판정 결과
- 입력 발화 수와 생성 Window 수
- 모델·보정기·특징 추출기 버전
- 모델 파일 SHA-256
- 분석 제한사항

## 7. 설명 가능성 구현

Random Forest가 변수 조합을 비선형으로 학습했으므로 `위협 표현 1개 = 20점` 같은 임의 배점을 만들지 않는다.

설명은 두 층으로 나눈다.

1. **탐지 근거**: 어떤 문구가 어떤 변수로 변환됐는지 표시
2. **모델 기여도**: TreeSHAP으로 해당 변수가 이번 예측을 얼마나 올리거나 내렸는지 표시

SHAP을 사용할 수 없으면 탐지 근거와 추출값만 제공하고, 이를 모델 기여도라고 표현하지 않는다.

## 8. 권장 파일 구조

```text
dashboard/
├─ components/
│  └─ demo.py                  # Streamlit 화면 구성
├─ services/
│  ├─ detection_service.py     # 전체 분석 흐름과 판정 정책
│  ├─ feature_extractor.py     # 전처리·Window·12개 특징 생성
│  ├─ model_loader.py          # 모델·보정기 안전 로딩
│  └─ explanation_service.py   # 근거 문구·SHAP 설명
├─ models/
│  ├─ window_model.joblib
│  ├─ window_calibrator.joblib
│  ├─ case_model.joblib
│  ├─ case_calibrator.joblib
│  └─ model_manifest.json
├─ data/ml_validation/
│  ├─ risk_score_config_07.json
│  └─ threshold_policy_config_08.json
└─ demo_py_설계.md
```

`demo.py` 한 파일에 모델 로딩·특징 추출·화면 코드를 모두 넣지 않는다. UI와 분석 로직을 분리해야 이후 모델 교체와 단위 테스트가 쉽다.

## 9. 구현 전 필수 준비사항

현재 저장소에는 평가 CSV와 점수·임계값 JSON은 있지만, 실제 추론에 필요한 모델과 보정기 `joblib` 파일은 포함되어 있지 않다. 따라서 다음 파일을 학습 Colab에서 먼저 내보내야 한다.

- 최종 Window Random Forest 모델
- Window Platt 보정기
- 최종 Case `STACKED_SAFE` Random Forest 모델
- Case Identity 보정기 또는 동일 처리 함수
- 정확한 Case·Window 특징 컬럼 순서
- 학습 당시와 동일한 특징 추출 규칙 및 버전
- 모델 버전·학습일·입력 해시가 포함된 manifest

모델 파일이 없거나 특징 순서가 다르면 임의 점수를 만들지 않고 다음 메시지를 표시한다.

```text
모델 파일 또는 특징 정의를 찾을 수 없어 실제 위험점수를 계산할 수 없습니다.
```

신뢰하지 않는 외부 `joblib` 또는 Pickle 파일은 실행 코드가 포함될 수 있으므로 불러오지 않는다.

## 10. 구현 순서

1. Colab에서 최종 모델·보정기·특징 명세 export
2. 동일 입력에 대해 Colab과 로컬 점수가 일치하는 기준 사례 작성
3. `feature_extractor.py` 구현 및 특징값 단위 테스트
4. `model_loader.py`와 모델·manifest 무결성 검사 구현
5. Window 점수와 Case 종합점수 계산 구현
6. 판정 정책과 근거 문구·SHAP 설명 구현
7. `demo.py` Streamlit UI 구현
8. 정상형·피싱형·애매한 문장·짧은 입력으로 시나리오 테스트

## 11. 완료 기준

- 같은 테스트 입력에 대해 Colab과 데모의 특징값·점수가 일치한다.
- Window는 10개 발화·간격 5 기준으로 생성된다.
- Window는 Platt, Case는 Identity 보정이 적용된다.
- Window 69점, Case 58점 기준이 설정 JSON에서 읽힌다.
- Case 점수를 최종 종합 위험점수로 명확히 표시한다.
- 의심 문구와 모델 변수를 연결해 보여준다.
- 정상 확정·실제 피해확률·금융기관 확정판정처럼 과장하지 않는다.
- 모델이나 설정 파일이 없으면 가짜 결과 대신 명확한 오류를 표시한다.
- 개인정보를 저장하거나 로그에 남기지 않는다.
