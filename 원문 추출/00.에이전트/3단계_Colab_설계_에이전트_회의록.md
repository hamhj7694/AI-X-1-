# 3단계 Colab 설계 에이전트 회의록

## 요약

`01 데이터셋 구축 → 02 ML 보조 라벨링 → 03 ML 학습·평가`로 노트북을 분리하는 방향은 타당하다.
다만 데이터 누출, 출처 편향, SILVER 라벨 순환평가를 자동으로 차단하는 조건을 넣는다는 전제의 **조건부 승인**이다.

가장 먼저 `01_dataset_building_v2`를 확정하고 검증한 뒤 02, 03 순서로 하나씩 제작한다.

## 참석 역할

- 라우터 및 오케스트레이션: 작업 분리와 의견 조정
- 데이터분석가: 단위·스키마·변수 의미 검토
- 검증가: 데이터 누출·평가 신뢰성 독립 감사
- 개발자: Colab 실행·재현·저장 구조 검토
- 교육 강사: 수업 수준의 코드·주석·셀 구성 검토
- 머신러닝 전문가: 학습 문제·모델·평가 설계
- 문서 작성 담당: 최종 합의와 분석 결과를 사용자 양식에 맞게 문서화

## 교육용 코드 스타일 검토

공유된 Google Drive의 다음 강의 Colab을 표본 검토했다.

- 로지스틱 회귀
- 의사결정나무
- 랜덤포레스트
- 부스팅
- K-means 군집화

공통 스타일은 짧은 한글 제목, 번호가 붙은 단계별 코드, 코드 옆 쉬운 한글 주석,
훈련·테스트 분리, 예측값과 실제값 비교, 혼동행렬과 성능지표 해석, 마지막 시각화이다.
신규 노트북도 이 흐름을 따르되 같은 원본 통화가 학습과 평가에 섞이지 않도록 그룹 분할을 추가한다.

## 확인된 현재 데이터 사실

- 보이스피싱 `cases.json`: 402개
- 정상 금융상담 ZIP: Drive에는 12개
- 현재 스크립트가 처리하는 정상상담 ZIP: `TL_`, `VL_` 6개
- `TS_`, `VS_`는 대응 원천자료로 중복을 피하기 위해 제외
- 금액 이벤트 추가 후 논리적 데이터테이블: 총 17개
- `fraud_detection_ml`은 이미 정상상담과 보이스피싱을 공통 학습 스키마로 결합
- 우체국 실제 피해액은 금감원 녹취 사건과 연결되지 않음
- 금감원 녹취에는 사건별 실제 피해 발생 여부와 확정 피해액 정답이 없음

보고서에는 “정상상담 ZIP 12개를 모두 사용”이 아니라 다음과 같이 작성한다.

> 정상 금융상담 ZIP 12개 중 중복을 피하기 위해 라벨링 데이터인 TL·VL ZIP 6개를 처리하였다.

## 핵심 위험과 대응

### 1. 출처 편향

금감원 자료는 모두 사기, 별도 금융상담 자료는 모두 정상이다. 모델이 범죄 언어가 아니라
전사 품질, 문체, 화자 태그, 마스킹 형태, 대화 길이를 구분할 수 있다.

대응:

- 정상·사기 모두 같은 텍스트 정규화와 구간 생성 방식 적용
- 경로, 파일명, 폴더명, 출처, 상담 주제, 화자 태그를 모델 입력에서 제외
- 1차 모델은 `model_input_text`만 사용
- 대화 길이 분포와 출처별 특징을 별도 진단
- 결과를 “두 공개 코퍼스 구분 성능”으로 제한해 해석

### 2. 동일 원본 누출

같은 파일의 여러 사건이나 같은 통화의 겹치는 구간이 학습과 평가에 나뉘면 성능이 부풀려진다.

대응:

- `file_id/group_id` 기준 `GroupShuffleSplit` 또는 `StratifiedGroupKFold` 사용
- 모든 사건과 겹치는 구간을 동일 분할에 배치
- 분할 ID와 시드를 저장하고 그룹 교집합이 0인지 자동 검사

### 3. SILVER 라벨 순환평가

규칙으로 만든 라벨을 모델이 학습하고 같은 규칙 라벨로 평가하면 실제 정확도를 검증한 것이 아니다.

대응:

- `rule_label`, `model_label`, `human_label`을 별도 보존
- 사람 정답 GOLD에서만 실제 Precision·Recall·F1 계산
- GOLD가 없으면 모델 결과는 `MODEL_CANDIDATE` 또는 `SILVER`로 유지
- 규칙·모델 불일치와 저신뢰 사례를 우선 검수

### 4. 실제 피해 라벨 부재

요구, 합의, 이체완료 주장은 녹취에서 확인할 수 있지만 실제 금융피해 발생을 의미하지 않는다.

대응:

- `실제 피해 발생 예측` 모델은 만들지 않음
- `대화상 위험 진행 단계` 또는 `피해자 순응 반응` 모델로 한정
- 실제 피해액은 외부 금융·신고자료가 개별 사건과 연결된 경우에만 사용
- 순응 예측에는 예측 시점 이후 발화를 사용하지 않음

## 노트북 1: `01_dataset_building_v2.ipynb`

### 목적

원본을 파일·사건·발화·이벤트로 구조화하고 규칙 기반 SILVER 라벨 및 ML 공통 스키마를 만든다.

### 권장 셀 순서

1. 목적·입력·17개 출력 설명
2. 라이브러리 설치 및 불러오기
3. Drive 연결, 경로와 설정값
4. 입력 개수와 스키마 확인
5. 공통 텍스트 전처리와 원문 보존
6. 파일·사건·발화 표 생성
7. 사칭·행동·심리전략 SILVER 라벨 생성
8. 언급·요구·합의·완료주장 금액 이벤트 생성
9. 정상상담과 우체국 자료 표준화
10. 표준 8개·ML 준비 4개·대시보드 5개 생성
11. 중복·결측·참조무결성 검증
12. CSV·Parquet 및 manifest 저장
13. 결과 미리보기·해석·한계

### 필수 수정

- 정상상담의 `original_split`을 ML 공통표까지 보존
- 공통 탐지표에 `sample_id`, `conversation_id`, `group_id`, `class_label`,
  `source_dataset`, `original_split`, `sample_scope`, 구간정보, 텍스트, 발화 수, 품질정보 포함
- 입력 해시, 패키지 버전, 규칙 버전, 설정, seed 저장
- `old` 폴더 자동검색 금지: 정확한 `build_voicephishing_datasets_v2.py` 경로 사용
- 오류 파일 목록, 외래키 오류, 중복·근접중복, 개인정보 마스킹 상태 기록

### 통과 조건

- 보이스피싱과 정상상담 입력이 모두 1건 이상
- 기본키 중복 0, 필수 ID 누락 0, 외래키 고아 0
- `raw_text`와 `normalized_text` 별도 보존
- 실제 피해액과 녹취 금액 상태 분리
- 17개 테이블과 manifest·검증보고서 정상 저장

## 노트북 2: `02_ml_assisted_labeling.ipynb`

### 목적

사칭 대상, 요구 행동, 심리전략, 금액 상태를 규칙과 독립적인 모델로 다시 판정하고
불일치·저신뢰 사례를 검수 대상으로 만든다.

### 권장 셀 순서

1. 구축 테이블 불러오기
2. X·y와 분석 단위 설명
3. GOLD 입력용 층화표본 생성
4. GOLD 라벨 수와 클래스 분포 확인
5. 파일·사건 기준 그룹 분할
6. TF-IDF 단어·문자 n-gram 비교
7. 단일라벨 Logistic Regression 학습
8. 다중라벨 One-vs-Rest 학습
9. 예측값·실제값 비교
10. 혼동행렬과 Micro·Macro F1
11. 전체 예측, 규칙·모델 비교, 검수 우선순위 저장
12. 모델·설정·한계 저장

### 실행 방식

GOLD가 부족하면 검수표만 생성하고 학습은 자동 중단한다. 사용자가 GOLD를 입력한 뒤 다시 실행하면 학습과 비교가 진행되는 2회 실행 구조로 만든다.

### 확정된 사람 검수 범위

전체 발화를 사람이 분류하지 않고 Colab이 핵심 발화 30~50개를 자동 선정한다.

선정 우선순위:

1. 규칙과 ML 결과가 불일치한 발화
2. 두 결과의 신뢰도가 낮은 발화
3. 희귀 사칭 대상·요구 행동·심리전략이 포함된 발화
4. 금액 요구·합의·이체완료 주장이 포함된 발화
5. 변조음성·다중사건·역할 불확실 발화
6. 규칙과 ML 결과가 일치한 발화 중 무작위 비교 표본

`네`, `예`, 단순 인사처럼 단독으로 의미가 부족한 발화는 원칙적으로 제외하되,
직전 금액 요구에 대한 합의처럼 앞 발화와 연결해야 의미가 생기는 경우에는 문맥과 함께 포함한다.

사용자는 검수표의 `사람정답`과 필요 시 `검수메모`만 입력한다.
30~50개는 모델 학습에 충분한 대규모 정답셋이 아니라 최소 검증 표본이므로,
클래스별 표본이 부족하면 정량평가 대신 사례 검토와 오류 유형 분석에 사용한다.

### 출력

- `gold_label_template`
- `ml_label_predictions`
- `rule_ml_comparison`
- `human_review_queue`
- `labeling_metrics`
- 저장된 모델 파이프라인

## 노트북 3: `03_ml_training_evaluation.ipynb`

### 목적

정상상담 vs 보이스피싱, 대출사기형 vs 수사기관사칭형을 분류하고 유사 사건을 군집화한다.

### 권장 셀 순서

1. ML 준비 테이블 불러오기
2. 세 분석 과제 설명
3. X·y·group과 클래스 분포 확인
4. 그룹 기준 학습·평가 분리
5. Dummy 기준모델 학습
6. TF-IDF + Logistic Regression·Linear SVM 학습
7. 예측값과 실제값 비교
8. 혼동행렬, Precision, Recall, F1, PR-AUC
9. 주요 단어와 모델 계수 해석
10. TF-IDF/임베딩 + K-means 군집화
11. Silhouette, 대표 문장, 군집 안정성 평가
12. 예측표·그림·모델·대시보드 요약 저장

### 해석 제한

- 정상·사기 결과는 우선 두 공개 코퍼스 구분 성능이다.
- 폴더에서 얻은 사기유형은 사건별 GOLD가 아니라 `SOURCE_WEAK_LABEL`이다.
- 군집화 결과에는 정확도라는 표현을 사용하지 않는다.
- 실제 피해 확률 모델은 만들지 않고 위험 진행 단계만 별도 실험한다.

## 최종 합의

1. 기존 노트북과 스크립트는 `old`에 보관한다.
2. 01 v2를 먼저 제작·실행·검증한다.
3. 01 통과 후 02를 만들고, GOLD 부족 시 검수표 생성까지만 수행한다.
4. 02와 독립적으로 가능한 정상·사기 분류, 유형분류, 군집화는 03에서 수행한다.
5. 각 단계는 자동 검증 gate를 통과해야 다음 단계 입력으로 사용한다.
6. 모든 노트북은 공유 강의의 단계형 한글 주석 스타일을 따른다.
7. 보고서 초안은 문서 작성 담당이 사용자 양식에 맞춰 작성하고 검증가가 수치·과장 표현을 최종 확인한다.
8. 02단계의 사람 검수는 전체가 아닌 Colab이 선정한 핵심 발화 30~50개로 제한한다.

## 최종 권고 문구

> 세 개의 Colab으로 작업을 분리하는 설계는 데이터 구축 과정과 머신러닝 평가 과정을 명확히 구분하므로 적절하다. 다만 동일 원본 누출, 자료 출처 편향, 자동 SILVER 라벨의 순환평가를 방지하는 자동 검증 조건을 포함해야 한다. 이에 따라 01 데이터 구축 노트북부터 단계적으로 구현하고 검증한 후 다음 단계로 진행한다.
