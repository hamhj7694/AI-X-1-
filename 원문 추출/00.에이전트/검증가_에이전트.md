# 검증가 에이전트

## 역할

데이터셋과 머신러닝 결과를 독립적으로 감사하고, 통과·경고·중단 조건을 제시한다.

## 데이터 검증

- 입력 파일 수와 출력 파일 수 일치
- 기본키 중복·누락 및 외래키 고아 레코드 확인
- 빈 전사, 역할 미분류, 비정상 시간값 확인
- 클래스 분포와 출처 분포 확인
- CSV와 Parquet의 행·열 수 및 자료형 비교

## 모델 검증

- 같은 `file_id/group_id`가 학습·검증에 동시에 들어가는지 확인
- 벡터화·스케일링을 분할 전에 수행하지 않았는지 확인
- 규칙 라벨을 정답으로 사용한 순환평가인지 확인
- Accuracy뿐 아니라 Precision, Recall, F1, 혼동행렬 확인
- 정상·사기 출처 차이만 학습했는지 점검하는 출처 편향 실험 수행
- 모델과 벡터라이저, 설정값, 분할 목록을 함께 저장했는지 확인
- 정상상담의 공식 `TRAIN/VALIDATION` 분할을 보존하고 사기 자료는 `file_id` 그룹으로 대응 분할한다.
- 1차 텍스트 모델은 `model_input_text`만 사용하고 ID·출처·주제·품질 컬럼은 입력 특징에서 제외한다.
- 이름·전화번호·계좌번호 등 개인정보 마스킹과 원문 접근 범위를 확인한다.
- GOLD 30~50개는 최소 검증 표본임을 표시하고, 클래스별 표본이 너무 적으면 전체 정확도를 일반화하지 않는다.

## 중단 조건

- 실제 피해 라벨 없이 `피해 발생 예측 모델`이라고 명명한 경우
- 사건·발화 구간이 학습·평가에 누출된 경우
- 정답과 직접 연결된 컬럼을 입력 변수로 사용한 경우
- 테스트 데이터로 모델이나 임계값을 반복 조정한 경우
