# 05 데이터셋별 확인 가능 내용과 가설 후보

참고 문서: [`05_dataset_columns_dictionary.md`](./05_dataset_columns_dictionary.md)

이 문서는 `01_standard_tables`의 각 파일에서 **무엇을 직접 확인할 수 있는지**, 그리고 이후 어떤 가설을 검토할 수 있는지를 정리한다.

## 가설 사용 원칙

- 아래 가설은 아직 검증된 결론이 아니라 분석 후보이다.
- 사건 수를 셀 때는 `case_id`, 원본 파일 수를 셀 때는 `file_id`, 발화 수를 셀 때는 `turn_id`를 사용한다.
- 사칭·행동·전략·금액 표는 사건당 여러 행이 존재하므로 단순 행 수를 사건 수로 해석하지 않는다.
- 자동 추출 결과는 `evidence_text`, `extraction_method`, `extraction_confidence`, `label_status`로 검증한다.
- `amount_krw`는 언급 금액이며 실제 피해액이 아니다. 실제 피해액은 `verified_loss_amount_krw`와 `verification_status`가 유효할 때만 사용한다.
- 정상상담과 보이스피싱 비교에서는 표본 수뿐 아니라 출처, 기간, 통화 길이, 상담 주제 차이를 함께 통제한다.

# 1. `vp_files` — 원본 파일

## 이 파일만으로 직접 확인 가능한 내용

- 원본 파일 총개수와 `source_category`별 구성
- MP3 등 원본 `media_type` 구성
- 파일 길이 `duration_sec`의 분포
- 파일별 사건 수 `case_count`와 발화 수 `turn_count`
- 한 파일에 여러 사건이 포함된 `multi_case_file` 비율
- 빈 전사 `empty_transcript`와 `quality_flag` 분포
- `publication_date`가 존재하는 파일의 게시 시기
- `media_composition`별 파일 구성

## 확인 가능한 기술적 질문

1. 어떤 `source_category`의 원본 파일이 가장 많은가?
2. 파일 길이는 특정 구간에 집중되는가?
3. 긴 파일일수록 사건과 발화가 더 많이 분리되는가?
4. 다중사건 파일은 어느 원본 분류에서 많이 나타나는가?
5. 품질 이상 또는 빈 전사는 특정 미디어 유형에 집중되는가?
6. 게시일 결측은 얼마나 되며 기간 분석이 가능한 수준인가?

## 가설 후보

| 가설 | 주요 컬럼 | 분석 단위 | 권장 확인 방법 |
|---|---|---|---|
| 파일 길이가 길수록 분리 사건 수가 많다 | `duration_sec`, `case_count` | 파일 | 산점도, Spearman 상관 |
| 파일 길이가 길수록 발화 수가 많다 | `duration_sec`, `turn_count` | 파일 | 산점도, Spearman 상관 |
| 다중사건 파일은 단일사건 파일보다 길다 | `multi_case_file`, `duration_sec` | 파일 | 중앙값·분포, Mann–Whitney |
| 원본 분류에 따라 파일 길이 분포가 다르다 | `source_category`, `duration_sec` | 파일 | 박스플롯, Kruskal–Wallis |
| 품질 상태에 따라 빈 전사 비율이 다르다 | `quality_flag`, `empty_transcript` | 파일 | 교차표, Fisher/카이제곱 |

## 다른 표와 연결하면 볼 수 있는 내용

- `file_id`로 `vp_cases`를 연결하여 실제 사건 수와 `case_count` 일치 여부 확인
- `file_id`로 `vp_utterances`를 연결하여 실제 발화 수와 `turn_count` 일치 여부 확인
- 동일 원본 파일의 사건이 학습·평가 데이터에 동시에 들어가는 데이터 누수 가능성 확인

## 제한과 주의사항

- `publication_date`가 실제 범죄 발생일인지 확인되지 않았다.
- `source_category`는 원자료 분류이므로 사건 수준 정답 라벨과 동일하다고 단정할 수 없다.
- `source_file` 파일명에 사건 설명이 포함돼 있다면 텍스트 모델에서 라벨 누수가 발생할 수 있다.

# 2. `vp_cases` — 보이스피싱 사건

## 이 파일만으로 직접 확인 가능한 내용

- 보이스피싱 사건 총수와 `source_category`, `supervised_target` 구성
- 사건별 통화 길이, 발화 수, 화자 수
- 범죄자·피해자·역할불명 발화 수와 비율
- 원본·정규화 텍스트와 범죄자·피해자 역할별 텍스트
- ASR 관련 품질, 검토 필요 여부, 품질 상태
- 사건별 대표 사칭기관·직책과 사칭 전환 순서
- 사건별 대표 요구행동과 최초 위험행동 등장 시점
- 최대 언급 금액
- 자동 검출된 전략별 횟수와 전략 다양성
- 복수 사칭 여부

## 확인 가능한 기술적 질문

1. 사건 유형별 사건 수와 통화 길이는 어떻게 다른가?
2. 범죄자와 피해자의 발화 비중은 사건 유형별로 다른가?
3. 주요 사칭기관과 주요 요구행동은 어떻게 구성되는가?
4. 한 사건에서 사칭기관이 몇 번, 어떤 순서로 바뀌는가?
5. 위험 요구행동은 통화의 어느 시점에 처음 등장하는가?
6. 긴급성·협박·비밀유지 등 자동 검출 전략은 어떤 유형에서 많이 기록되는가?
7. 품질이 낮거나 역할불명 비율이 높은 사건에서 자동 추출 결과가 더 많이 검토 대상으로 표시되는가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 사기유형에 따라 통화 길이와 발화 수가 다르다 | `supervised_target`, `duration_sec`, `turn_count` | 분포 비교, Mann–Whitney/Kruskal–Wallis |
| 사기유형에 따라 주요 사칭 대상이 다르다 | `supervised_target`, `primary_impersonation_subtype` | 교차표, 카이제곱, Cramér’s V |
| 사기유형에 따라 주요 요구행동이 다르다 | `supervised_target`, `primary_requested_action` | 교차표, 사건 비율 |
| 기관사칭형은 대출사기형보다 권위·공포 전략이 많이 검출된다 | `supervised_target`, `authority_trust_count`, `fear_threat_count` | 중앙값·분포 비교, 근거 문장 검수 |
| 대출사기형은 혜택약속·금전요구 표현이 많이 검출된다 | `supervised_target`, `benefit_promise_count`, `money_request_count` | 중앙값·존재율 비교 |
| 복수 사칭 사건은 단일 사칭 사건보다 전략 다양성이 높다 | `has_multiple_impersonations`, `strategy_diversity` | 분포 비교 |
| 통화가 길수록 전략 다양성이 높다 | `duration_sec`, `strategy_diversity` | Spearman 상관; 길이 효과 주의 |
| 최초 위험행동 등장 시점은 사기유형별로 다르다 | `first_risky_action_sec`, `duration_sec`, `supervised_target` | 상대시점으로 변환 후 분포 비교 |
| 역할불명 비율이 높을수록 검토 필요 표시가 많다 | `unknown_role_ratio`, `needs_review` | 로지스틱 비교 또는 구간별 비율 |

## 텍스트에서 확인할 수 있는 내용

- `normalized_offender_text`: 범죄자가 사용하는 표현과 문장 구조
- `normalized_victim_text`: 피해자의 질문·의심·응답 표현
- `normalized_full_text`: 전체 통화 흐름과 문맥
- `raw_*`: 정규화 과정에서 정보가 손실됐는지 확인

## 제한과 주의사항

- 전략 횟수와 주요 사칭·행동은 자동 추출 결과가 포함돼 있다.
- 통화가 길면 단순 횟수가 커질 가능성이 있으므로 `1,000자당 횟수`나 사건 존재율도 함께 봐야 한다.
- `mentioned_amount_max_krw`는 피해액이 아니라 최대 언급 금액이다.
- `primary_*`는 대표값 하나이므로 사건에 존재하는 모든 사칭·행동을 나타내지 않는다.

# 3. `vp_utterances` — 발화

## 이 파일만으로 직접 확인 가능한 내용

- 사건별 발화 순서와 시작·종료 시간
- 발화별 원문·정규화문·분석용 텍스트
- 화자 ID와 자동 추정 역할
- 범죄자·피해자·불명 역할별 발화 수와 길이
- 짧은 발화, 저정보 발화, 변조 음성, 품질 상태
- 음성인식 평균 신뢰 관련 값

## 확인 가능한 기술적 질문

1. 범죄자와 피해자의 평균·중앙 발화 길이는 다른가?
2. 통화 초반과 후반에 사용되는 표현이 달라지는가?
3. 역할불명 발화는 어느 사건과 구간에 집중되는가?
4. 짧거나 저정보인 발화는 어느 화자 역할에 많은가?
5. ASR 신뢰 관련 값이 낮은 발화에서 저정보·품질 이상 표시가 증가하는가?
6. 동일 사건 내 발화 순서와 시간이 논리적으로 보존되어 있는가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 범죄자 역할 발화는 피해자 역할 발화보다 길다 | `auto_role`, `duration_sec`, `content_text` | 사건을 군집으로 고려한 분포 비교 |
| 통화 후반으로 갈수록 범죄자 발화의 위험행동 표현이 증가한다 | `turn_order`, `content_text`, `auto_role` | 상대 발화순서 구간별 존재율 |
| 화자 역할 점수가 낮을수록 `UNKNOWN` 또는 검토 대상이 많다 | `role_heuristic_score`, `auto_role`, `quality_flag` | 구간별 비율 |
| ASR 신뢰 관련 값이 낮을수록 저정보 발화가 많다 | `avg_logprob`, `is_low_information` | 분포·상관 비교 |
| 변조 음성 발화는 특정 원본 파일에 집중된다 | `voice_modified`, `file_id` | 파일별 비율 |

## 다른 표와 연결하면 볼 수 있는 내용

- 이벤트 표의 `evidence_turn_id`를 `turn_id`에 연결하여 자동 추출 문장의 앞뒤 발화 확인
- `case_id`로 사기유형을 연결하여 유형별 대화 흐름 비교
- 사칭 → 압박 → 요구행동 → 금액 언급의 등장 순서 구성

## 제한과 주의사항

- `auto_role`은 사람이 확정한 역할이 아니라 자동 추정값이다.
- 발화들은 서로 독립된 표본이 아니며 동일 사건에 중첩돼 있다.
- 발화 행을 그대로 통계 표본으로 사용하면 발화가 긴 사건의 영향이 과대해질 수 있다.

# 4. `vp_impersonations` — 사칭 이벤트

## 이 파일만으로 직접 확인 가능한 내용

- 사칭 상위 그룹과 세부 유형
- 주장 기관명, 부서명, 직책, 인물명, 관계
- 신분을 주장하는 방식
- 사건의 대표 사칭 여부와 후보 순위
- 최초 사칭 언급 순서·시점과 언급 횟수
- 사칭기관의 통화 내 역할
- 실제 근거 문장
- 추출 방법·버전·신뢰도·검토 상태

## 확인 가능한 기술적 질문

1. 가장 많이 등장하는 사칭 그룹과 세부 유형은 무엇인가?
2. 사건 기준으로 가장 많이 사칭되는 기관·직책은 무엇인가?
3. 대표 사칭과 보조 사칭은 어떻게 다른가?
4. 한 사건에서 여러 기관이 함께 등장하는 비율은 얼마인가?
5. 사칭기관별 최초 등장 시점이 다른가?
6. 명시적 신분 주장과 단순 기관 언급은 어떻게 구분되는가?
7. 신뢰도가 낮거나 검토가 필요한 사칭 유형은 무엇인가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 사칭 그룹에 따라 주장 직책 분포가 다르다 | `impersonation_group`, `claimed_role_title_normalized` | 교차표, 희소범주 통합 |
| 공공기관 사칭은 금융기관 사칭보다 통화 초반에 등장한다 | `impersonation_group`, `first_mention_sec` | 사건 길이 대비 상대시점 비교 |
| 대표 사칭은 보조 사칭보다 언급 횟수가 많다 | `is_primary_impersonation`, `mention_count` | 분포 비교 |
| 복수 사칭 사건은 특정 기관 조합에 집중된다 | `case_id`, `impersonation_subtype` | 사건별 조합 빈도 |
| 명시적 신분 주장은 높은 대표 사칭 점수와 연관된다 | `identity_claim_type`, `case_candidate_score` | 그룹별 분포 |

## 제한과 주의사항

- 한 사건에 여러 사칭 행이 있으므로 `case_id + impersonation_subtype`을 중복 제거해 사건 비율을 계산한다.
- 단순 기관 언급을 실제 사칭으로 잘못 검출했을 수 있으므로 `identity_claim_type`과 `evidence_text`를 확인한다.
- `claimed_person_name_raw`는 개인정보 취급에 유의하고 가능한 경우 마스킹 컬럼을 사용한다.

# 5. `vp_requested_actions` — 요구행동 이벤트

## 이 파일만으로 직접 확인 가능한 내용

- 요구행동 상위 그룹과 세부 유형
- 행동이 언급·확정된 상태
- 행동과 관련된 언급 금액
- 사건의 대표 요구행동 여부
- 최초 언급 순서·시점과 언급 횟수
- 행동 근거 문장과 근거 화자 역할
- 추출 방법·신뢰도·버전·라벨 상태

## 확인 가능한 기술적 질문

1. 피해자에게 가장 자주 요구된 행동은 무엇인가?
2. 송금·현금인출·앱 설치·정보제공 요구의 사건 비율은 얼마인가?
3. 대표 요구행동과 보조 요구행동은 어떻게 다른가?
4. 요구행동이 통화의 어느 시점에 처음 등장하는가?
5. 행동 유형별 관련 언급 금액은 어떻게 다른가?
6. 범죄자 이외 화자의 문장이 요구행동으로 검출된 사례가 있는가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 행동 유형에 따라 최초 등장 시점이 다르다 | `action_type`, `first_mention_sec` | 상대시점 분포 비교 |
| 대표 행동은 보조 행동보다 언급 횟수가 많다 | `is_primary_action`, `mention_count` | 분포 비교 |
| 송금·현금 행동은 다른 행동보다 큰 금액과 함께 언급된다 | `action_type`, `mentioned_amount_krw` | 중앙값·분포; 금액 의미 검수 |
| 사건에는 하나의 요구보다 여러 단계 행동 조합이 나타난다 | `case_id`, `action_type` | 사건별 행동 조합 빈도 |
| 행동 그룹별 자동 추출 신뢰도에 차이가 있다 | `action_group`, `extraction_confidence` | 그룹별 분포와 수동 표본검수 |

## 다른 표와 연결하면 볼 수 있는 내용

- 사칭기관별 요구행동 차이
- 심리전략이 나온 뒤 요구행동까지 걸린 발화·시간 간격
- 요구행동과 금액 방향·용도의 결합

## 제한과 주의사항

- 행동 언급이 실제 수행을 의미하지 않는다.
- `evidence_role`이 `OFFENDER`인지 확인해야 한다.
- 검출되지 않은 사건을 ‘행동이 없었다’고 단정하려면 추출 재현율 검증이 필요하다.

# 6. `vp_strategy_events` — 전략 이벤트

## 이 파일만으로 직접 확인 가능한 내용

- 자동 검출된 전략 유형
- 전략이 등장한 발화 순서와 시점
- 전략 근거 문장과 근거 화자 역할
- 추출 방법·신뢰도·버전·라벨 상태
- 사건별 전략 유형 수와 반복 양상

## 확인 가능한 기술적 질문

1. 어떤 전략 유형이 가장 많은 사건에서 검출되는가?
2. 전략별 언급 횟수와 사건 존재율은 어떻게 다른가?
3. 전략 유형마다 통화에서 등장하는 시점이 다른가?
4. 한 사건에서 어떤 전략들이 함께 등장하는가?
5. 근거 화자가 범죄자인 전략 이벤트의 비율은 얼마인가?
6. 추출 신뢰도와 라벨 상태는 전략 유형별로 다른가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 권위·정당성 형성은 통화 초반에 많이 등장한다 | `strategy_type`, `turn_order`, `mention_sec` | 상대시점 구간별 존재율 |
| 금전요구·행동통제는 통화 후반에 많이 등장한다 | `strategy_type`, `turn_order`, `mention_sec` | 상대시점 분포 비교 |
| 공포·위협과 긴급·시간압박은 같은 사건에서 함께 나타난다 | `case_id`, `strategy_type` | 사건 존재 여부 교차표, lift/phi |
| 비밀유지와 정보요구는 같은 사건에서 함께 나타난다 | `case_id`, `strategy_type` | 사건 존재 여부 교차표 |
| 전략 유형에 따라 자동 추출 신뢰도가 다르다 | `strategy_type`, `extraction_confidence` | 분포 비교, 수동 검수 |

## 정상상담과 비교할 수 있는 가설

`normal_finance_calls.normalized_text`에 **동일한 규칙을 다시 적용했을 때만** 다음을 비교할 수 있다.

- 비밀유지 표현은 정상 금융상담보다 보이스피싱 사건에서 더 높은 비율로 나타나는가?
- 긴급성·위협 표현은 정상상담보다 보이스피싱에서 더 높은가?
- 금전 관련 표현 자체보다 ‘금전요구 + 긴급성’ 조합이 더 구별력이 있는가?

## 제한과 주의사항

- `strategy_type`은 심리상태의 직접 측정값이 아니라 규칙에 걸린 표현 유형이다.
- 단순 행 수는 긴 사건에 유리하므로 사건 존재율과 길이 보정 밀도를 함께 확인한다.
- 결과를 해석할 때 항상 `evidence_text`의 정탐·오탐 예시를 제시한다.

# 7. `vp_amount_events` — 금액 이벤트

## 이 파일만으로 직접 확인 가능한 내용

- 통화에서 언급된 원화 환산 금액과 원문 표현
- 금액의 상태, 자금 방향, 용도
- 관련 요구행동
- 금액이 직접 언급됐는지 문맥에서 추정됐는지
- 검증된 피해액과 검증 상태가 존재하는지
- 금액 근거 문장과 근거 화자 역할
- 자동 추출 방법·신뢰도·버전

## 확인 가능한 기술적 질문

1. 통화에서 언급되는 금액의 분포는 어떠한가?
2. 금액 용도는 대출원금·잔액·수수료·세금 등 어떻게 구성되는가?
3. 송금·입금·출금 등 방향이 명확한 금액의 비율은 얼마인가?
4. 금액 유형별로 실제 근거 문장은 어떻게 다른가?
5. 문맥 추정 금액과 직접 언급 금액의 신뢰도 차이는 무엇인가?
6. 검증된 실제 피해액은 몇 건이며 분석 가능한 수준인가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 금액 용도에 따라 언급금액 분포가 다르다 | `amount_purpose`, `amount_krw` | 로그축 분포, Kruskal–Wallis |
| 자금 방향에 따라 관련 요구행동이 다르다 | `amount_direction`, `related_action_type` | 교차표 |
| 문맥 추정 금액은 직접 추출 금액보다 신뢰도가 낮다 | `inferred_from_context`, `extraction_confidence` | 분포 비교 |
| 피해액 검증 여부는 특정 금액 상태에 집중된다 | `verification_status`, `amount_status` | 교차표 |
| 사기유형별 금액 용도와 방향이 다르다 | `case_id` 연결, `amount_purpose`, `amount_direction` | 사건 유형 연결 후 교차표 |

## 제한과 주의사항

- `amount_krw`는 잔액, 벌금, 대출한도, 가상 피해금 등도 포함할 수 있다.
- 같은 문장에서 여러 금액이 추출되거나 같은 금액이 반복될 수 있다.
- 실제 피해 규모는 유효한 `verified_loss_amount_krw`만 사용하고 `verification_status`를 함께 제시한다.
- 극단적으로 큰 금액은 오류가 아니라 억 단위 표현일 수 있으므로 원문을 먼저 확인한다.

# 8. `normal_finance_calls` — 정상 금융상담

## 이 파일만으로 직접 확인 가능한 내용

- 정상 금융상담 통화 수와 날짜 분포
- 상담기관, 상담 대분류, 상담 주제
- 정상상담 원문과 정규화 텍스트
- 통화별 발화 수
- 고객 연령대와 성별
- 원자료의 학습·검증 분할

## 확인 가능한 기술적 질문

1. 정상상담은 어떤 기관·업무·주제로 구성되어 있는가?
2. 상담 주제별 텍스트 길이와 발화 수는 어떻게 다른가?
3. 연령대·성별 분포와 결측 정도는 어떠한가?
4. TRAIN과 VALIDATION의 기관·주제 분포가 유사한가?
5. 정상상담에서도 송금·계좌·개인정보·인증 관련 표현이 얼마나 나타나는가?
6. 특정 위험 키워드가 정상적인 업무 문맥에서 어떻게 사용되는가?

## 가설 후보

| 가설 | 주요 컬럼 | 권장 확인 방법 |
|---|---|---|
| 상담 주제에 따라 통화 발화 수가 다르다 | `consulting_topic`, `turn_count` | 주제별 분포 비교 |
| 기관에 따라 상담 주제 구성이 다르다 | `source_institution`, `consulting_topic` | 교차표 |
| TRAIN과 VALIDATION의 기관·주제 분포가 다르지 않다 | `dataset_split`, 기관·주제 | 분포 차이, 카이제곱 |
| 특정 금융 용어는 일부 정상상담 주제에 집중된다 | `consulting_topic`, `normalized_text` | 문서 존재율 |
| 연령대에 따라 상담 주제 분포가 다르다 | `client_age_group`, `consulting_topic` | 교차표; 결측·대표성 주의 |

## 보이스피싱 데이터와 비교 가능한 가설

| 가설 | 정상 데이터 | 보이스피싱 데이터 | 주의사항 |
|---|---|---|---|
| 특정 표현의 통화 존재율이 다르다 | `normalized_text` | `vp_cases.normalized_offender_text` 또는 전체문 | 동일 전처리와 동일 분석단위 사용 |
| 텍스트 길이와 발화 수가 다르다 | `turn_count`, 텍스트 길이 | `vp_cases.turn_count`, 텍스트 길이 | 수집·전사 방식 차이 확인 |
| 위험 표현 조합이 보이스피싱에 더 집중된다 | 정상 원문에 동일 규칙 적용 | 사건 전략·행동과 원문 | 자동 추출 규칙의 정상 오탐 검수 |
| 기관·계좌·송금 단어만으로는 구분력이 낮다 | 정상 문서 존재율 | 사기 문서 존재율 | 단어보다 문맥·조합을 확인 |

## 제한과 주의사항

- 정상상담과 보이스피싱은 서로 다른 출처와 수집 과정에서 생성됐다.
- 정상상담 표본이 훨씬 많으므로 총 단어 수가 아니라 통화 존재율을 비교한다.
- 고객 연령·성별은 정상상담에만 존재하므로 보이스피싱 피해자 특성과 직접 비교할 수 없다.
- `source_date`와 보이스피싱의 `publication_date`를 같은 시간축으로 해석하지 않는다.

# 11. 현재 데이터만으로 검증하기 어려운 가설

다음 내용은 현재 표에 직접적인 정답 정보가 없거나 한쪽 데이터에만 있으므로 별도 자료가 필요하다.

- 보이스피싱 피해자의 연령·성별에 따른 위험 차이
- 실제 피해 발생 여부와 피해 성공률
- 실제 피해금액 전체 분포 — 검증 피해액이 충분한 경우에만 제한적으로 가능
- 통화 이후 신고·검거·피해구제 결과
- 범죄자의 실제 신원·조직·지역
- 피해자의 실제 감정·심리상태
- `publication_date`를 이용한 실제 발생 시계열 추세
- 특정 표현이 피해를 직접 유발했다는 인과관계

이 항목들은 현재 데이터에 존재하는 정보만으로는 결론을 내리지 않는다.
