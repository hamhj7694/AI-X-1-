# 머신러닝에서 무엇을 예측할 것인가

참고 문서:

- [`05_dataset_columns_dictionary.md`](./05_dataset_columns_dictionary.md)
- [`05_dataset_analysis_questions_and_hypotheses.md`](./05_dataset_analysis_questions_and_hypotheses.md)

## 결론

수집 한계를 반영하면 예측 과제를 다음처럼 구분해야 한다.

1. **즉시 진행 가능:** 보이스피싱 내부의 사기유형과 주요 사칭 대상
2. **조건부 진행:** 정상 금융상담인지 보이스피싱인지
3. **보조 기능:** 기존 보이스피싱 사례와의 유사도

정상·사기 이진 분류는 두 자료의 출처·전사 형식·스타일 차이를 모델이 학습하지 않는다는 검증을 통과해야만 의미가 있다. 보이스피싱 데이터만 학습하는 유사도 모델은 판정 모델이 아니라 유사 사례 검색과 신규 수법 탐지를 위한 보조 모델로 사용한다.

## 분석 설계를 바꾸는 수집 한계

### 1. 보이스피싱 자료는 전체 통화가 아닌 핵심 구간 발췌본

- `duration_sec`, `turn_count`, `first_*_sec`, `first_*_turn`, `mention_sec`, `turn_order`를 실제 통화 길이·초반·후반·최초 시점으로 해석하지 않는다.
- 시간·길이 변수는 데이터 품질 점검과 발췌본 내부 문맥 정렬에만 사용한다.
- 위 변수는 보이스피싱 판정·사칭 대상 예측의 독립변수에서 기본적으로 제외한다. 포함하면 수집 방식이나 발췌 길이를 학습할 위험이 있다.

### 2. 정상상담과 보이스피싱의 자료 형식·스타일이 다름

- 높은 정확도가 범죄 내용이 아니라 화자 태그, 문장부호, 익명화 토큰, 문장 길이, 전사 관습, 출처별 상투문구에서 나왔을 수 있다.
- 이진 분류 성능은 스타일 교란 검증 전에는 실제 보이스피싱 탐지 성능으로 해석하지 않는다.
- 동일한 수집·전사 과정으로 만든 정상·사기 외부 테스트셋이 없으면 일반화 성능을 확정할 수 없다.

```text
신규 통화
   ↓
[모델 1] 정상 금융상담 vs 보이스피싱
   ├─ 정상 금융상담
   └─ 보이스피싱 의심
          ↓
[모델 2] 사기유형 분류
   ├─ 대출사기형
   ├─ 기관사칭형
   └─ 기타·불명확
          ↓
[모델 3] 주요 사칭 대상 분류
   ├─ 은행·금융기관
   ├─ 경찰
   ├─ 검찰
   ├─ 대출회사·캐피탈
   ├─ 가족·지인
   └─ 기타·복수 사칭
          ↓
[설명 모듈]
   ├─ 주요 위험 신호
   ├─ 실제 근거 문장
   └─ 유사 과거 사례
```

# 1. 정상 금융상담 vs 보이스피싱 예측

## 예측 질문

> 이 통화는 정상 금융상담인가, 보이스피싱인가?

이 모델은 필요하지만, 현재 데이터에서는 **스타일 교란 검증을 통과한 경우에만 개발하는 조건부 모델**이다.

## 종속변수 y

```text
fraud_label
```

예측 클래스:

```text
LEGITIMATE_FINANCIAL_CALL
VOICE_PHISHING
```

## 권장 데이터

```text
02_ml_tables/fraud_detection_ml.parquet
```

이 테이블에는 정상 금융상담과 보이스피싱 사례가 함께 들어 있다.

## 독립변수 X

### 1단계: 텍스트만 사용

- `model_input_text`
- 단어 TF-IDF
- 2-gram TF-IDF

텍스트만 사용한 모델을 먼저 기준 모델로 만든다.

### 2단계: 검증된 내용 특징 추가

- 송금·현금인출 요구 표현
- 앱 설치·원격접속 표현
- 개인정보·인증정보 요구 표현
- 긴급성·시간 압박 표현
- 공포·협박 표현
- 비밀 유지 표현
- 기관·직책 관련 표현

구조화 특징은 자동 추출 문장을 사람이 검토한 후 추가하는 것이 안전하다.

`duration_sec`, `turn_count`, 문장 길이, 줄바꿈 수, 문장부호 수, 화자 태그는 예측 특징이 아니라 **스타일 교란 진단용 변수**로 분리한다.

## 이진 분류 전에 반드시 수행할 스타일 교란 진단

### 진단 1: 형식 변수만으로 분류

내용 단어를 사용하지 않고 다음 변수만으로 정상·사기를 분류한다.

- 문자 수와 줄 수
- 평균 문장 길이
- 문장부호 비율
- 숫자·영문·마스킹 토큰 비율
- 화자 태그 개수
- 발췌본 기록 길이와 발화 수

형식 변수만으로 성능이 높으면 현재 데이터에서는 출처·스타일 누수가 강하다는 의미다.

### 진단 2: 단어·화법 중첩 확인

- 정상·사기 상위 단어와 2-gram 비교
- 문서 존재율 차이
- 어휘집합 Jaccard 유사도
- 정상에만 등장하는 단어와 사기에만 등장하는 단어 비율
- 두 집단에 공통으로 등장하는 금융용어의 실제 문맥
- 가장 구별력이 큰 단어가 범죄 내용인지 출처 표식인지 수동 검토

### 진단 3: 형식 정규화 전후 성능 비교

다음을 제거·통일한 모델과 원문 모델을 비교한다.

- 화자 태그
- 파일명·출처명
- 특수문자와 반복 문장부호
- 줄바꿈 형식
- `[MASK]` 등 출처별 익명화 표식
- 기관명 직접 표현 — 별도 ablation 실험

정규화 후 성능이 크게 하락한다면 기존 성능이 스타일에 의존했을 가능성이 크다.

### 진단 4: 출처 일반화 평가

- 동일 원본·출처가 학습과 테스트에 동시에 들어가지 않도록 그룹 분할
- 가능하면 특정 기관·상담 주제를 통째로 테스트셋에 홀드아웃
- 가장 바람직하게는 동일 수집·전사 방식의 신규 정상·사기 표본으로 외부 평가

## 이진 분류 진행·중단 기준

- 스타일 변수만 사용한 모델도 높은 성능 → 현재 자료로 이진 분류 결론을 내리지 않음
- 구별 단어 대부분이 출처·전사 표식 → 내용 기반 탐지 모델로 보고하지 않음
- 형식 정규화 후에도 성능이 유지되고 공통 어휘 문맥에서 차이가 확인됨 → 조건부로 모델 진행
- 동일 형식 외부 테스트에서도 성능 유지 → 실제 탐지 모델 후보로 승격

## 우선 비교할 알고리즘

- Logistic Regression
- Linear SVM
- Naive Bayes

초기 단계에서는 딥러닝보다 해석 가능한 선형 모델을 먼저 사용한다. 모델 계수를 통해 어떤 단어와 표현이 정상·사기 판정에 영향을 주는지 확인할 수 있다.

## 평가 기준

- 보이스피싱 Recall
- Precision
- F1-score
- PR-AUC
- 정상상담 오탐률
- Confusion Matrix

Accuracy만 사용하면 안 된다. 정상상담을 보이스피싱으로 잘못 분류하는 비율과 실제 보이스피싱을 놓치는 비율을 모두 확인해야 한다.

# 2. 보이스피싱만 학습하는 유사도 모델

## 예측 질문

> 신규 통화는 기존 보이스피싱 사례와 얼마나 유사한가?

## 출력 예시

```text
기존 보이스피싱과의 유사도: 0.72
최근접 보이스피싱 사건: vp_XXXXX
가장 유사한 기존 유형: 기관사칭형
```

## 가능한 방법

- TF-IDF 코사인 유사도
- 문장 임베딩 유사도
- 최근접 이웃 검색
- One-Class SVM
- Isolation Forest

## 적절한 사용 목적

- 가장 비슷한 과거 보이스피싱 사례 검색
- 기존 패턴과 다른 신규 수법 후보 발견
- 이진 분류 결과에 대한 보조 설명
- 보이스피싱 내부 패턴과의 거리 측정

## 판정 모델로 사용할 수 없는 이유

정상 금융상담을 학습하거나 평가하지 않았기 때문에 다음 값을 알 수 없다.

- 정상상담 오탐률
- 정밀도
- 특이도
- 정상과 사기를 나누는 임계값

따라서 보이스피싱 내부 유사도 분위수를 `보이스피싱 판정 기준`이라고 부르면 안 된다.

```text
방법 1: 정상 + 사기 지도학습 → 보이스피싱 판정 주 모델
방법 2: 보이스피싱 단독 학습 → 유사 사례 검색 보조 모델
```

# 5. 사칭 대상 모델의 라벨 누수 방지

종속변수가 `primary_impersonation_group` 또는 `primary_impersonation_subtype`이라면 다음 컬럼을 독립변수로 사용하면 안 된다.

```text
primary_impersonation_group
primary_impersonation_subtype
primary_claimed_org_name
primary_claimed_role_title
primary_impersonation_evidence
impersonation_transition_sequence
mentioned_impersonation_subtypes
explicit_claim_subtypes
```

이 컬럼들은 예측할 사칭 대상 자체를 직접 포함한다. 독립변수에 넣으면 모델이 사칭 대상을 추론하는 것이 아니라 정답을 그대로 읽게 된다.

## 텍스트 내부의 라벨 누수 선택

### 모델 A: 기관명 포함

예시:

```text
“서울중앙지검 김○○ 수사관입니다.”
```

기관명을 포함한 텍스트로 사칭 대상을 분류한다.

목적:

- 실제 자동 분류 성능 확인
- 통화에서 명시적으로 말한 사칭기관 탐지

### 모델 B: 기관명·직책 마스킹

기관명과 직책을 가린 뒤 행동과 대화 방식만 사용한다.

목적:

- 기관명을 직접 말하지 않아도 수법만으로 사칭 대상을 추정할 수 있는지 확인
- 모델이 기관명에만 의존하는지 검증

두 모델의 성능 차이를 비교하면 기관명 직접 언급이 예측에 얼마나 큰 영향을 주는지 알 수 있다.

# 6. 단일 클래스와 멀티라벨 사칭 분류

한 사건에서 경찰 → 검찰 → 금융감독원처럼 여러 기관을 사칭할 수 있다.

## 대표 사칭기관 분류

```text
y = primary_impersonation_subtype
```

- 한 사건당 대표 사칭 유형 하나
- 일반적인 다중 클래스 분류
- 첫 번째 버전에서 권장

## 전체 사칭기관 분류

```text
y = 사건에 등장한 모든 impersonation_subtype
```

예시:

```text
[POLICE, PROSECUTION, BANK]
```

- 한 사건에 여러 정답을 허용하는 멀티라벨 분류
- 대표 사칭기관 모델을 검증한 뒤 확장

# 7. Corr 히트맵의 역할

Corr 히트맵은 독립변수가 아니다. 독립변수들 사이의 상관관계와 중복성을 확인하는 EDA 도구다.

## 상관관계를 확인할 수치형 변수

```text
authority_trust_count
behavior_control_count
benefit_promise_count
fear_threat_count
information_extraction_count
isolation_secrecy_count
legitimacy_building_count
money_request_count
resistance_handling_count
urgency_time_pressure_count
strategy_diversity
risky_action_count
risky_action_diversity
```

이 변수들은 횟수형이고 0이 많으며 정규분포가 아닐 가능성이 높으므로 Pearson보다 **Spearman 상관계수**가 더 적절하다.

## 히트맵으로 확인할 수 있는 것

- 비슷한 특징들이 중복 측정되는가?
- 어떤 전략 횟수들이 함께 증가하는가?
- 발췌 길이가 모든 전략 횟수에 영향을 주는가? — 편집 편향 점검용
- 다중공선성이 큰 변수가 있는가?

## 히트맵으로 확인할 수 없는 것

- 어떤 변수가 특정 사칭기관을 잘 예측하는가?
- 어떤 특징이 보이스피싱을 유발하는가?
- 사칭기관과 특징 간 인과관계가 있는가?

사칭기관과 특징의 관계는 다음 방법으로 추가 확인한다.

- 사칭기관별 특징 존재율과 중앙값
- 카이제곱 또는 Fisher 검정
- Cramér’s V
- Kruskal–Wallis 검정
- 모델 계수
- permutation importance
- Confusion Matrix

# 8. 데이터 분리와 비교 가능성 원칙

같은 원본 파일에서 여러 사건이 분리되어 있으므로 행을 무작위로 나누면 안 된다.

```text
group_id = file_id
```

동일한 `file_id`에서 나온 모든 사건은 다음 중 한쪽에만 들어가야 한다.

- 학습 데이터
- 검증 데이터
- 테스트 데이터

같은 원본의 유사한 문장이 학습과 테스트에 동시에 들어가면 실제보다 성능이 높게 측정되는 데이터 누수가 발생한다.

정상상담도 동일 원자료가 중복될 가능성을 확인하고 `source_id` 또는 원자료 그룹 기준으로 분리한다.

그러나 그룹 분할만으로 정상·사기 자료의 형식 차이는 해결되지 않는다. 동일한 전처리, 같은 텍스트 단위, 가능한 한 유사한 상담 주제와 길이 조건으로 비교 표본을 구성하고도 성능이 유지되는지 확인해야 한다.

# 9. 최종 모델 구성

| 구분 | 입력 X | 예측값 y | 역할 | 우선순위 |
|---|---|---|---|---:|
| 모델 A | 보이스피싱 텍스트 | `supervised_target` | 대출사기형·기관사칭형 분류 | 1 |
| 모델 B | 범죄자 텍스트·검증된 내용 특징 | `primary_impersonation_group` 또는 `primary_impersonation_subtype` | 주요 사칭 대상 분류 | 2 |
| 진단 실험 | 정상·사기 형식 변수 | `fraud_label` | 출처·스타일 교란 수준 측정 | 3 |
| 조건부 모델 | 형식을 통일한 정상·사기 텍스트 | `fraud_label` | 교란 검증 통과 시 보이스피싱 여부 판정 | 4 |
| 보조 모델 | 보이스피싱 텍스트 | 기존 사례와의 유사도 | 유사 사례 검색·신규 패턴 후보 탐색 | 5 |

## 권장 개발 순서

1. 보이스피싱 내부 데이터와 자동 추출 라벨 품질 검증
2. 보이스피싱의 대출사기형·기관사칭형 분류
3. 주요 사칭 상위 그룹 분류
4. 표본이 충분한 세부 사칭 유형 분류
5. 기관명 포함 모델과 마스킹 모델 비교
6. 정상·사기 어휘·화법 중첩 및 스타일 교란 진단
7. 교란 검증을 통과한 경우에만 정상·사기 이진 분류
8. 보이스피싱 유사 사례 검색 기능 추가
9. 위험 신호와 실제 근거 문장 설명 기능 추가

# 10. 최종 결과 출력 예시

```text
보이스피싱 가능성: 87%
예상 사기유형: 기관사칭형
예상 주요 사칭: 검찰
주요 위험 신호: 비밀 유지 + 공포·협박 + 계좌이체 요구
근거 문장: “수사 중이므로 가족에게 알리지 마십시오.”
유사 과거 사례: vp_XXXXX
```

## 핵심 정리

- 현재 우선 예측값: 대출사기형·기관사칭형 등 보이스피싱 내부 사기유형
- 다음 예측값: 주요 사칭 대상
- 조건부 예측값: 스타일 교란 검증을 통과한 경우의 보이스피싱 여부
- 보이스피싱 단독 학습 결과: 판정값이 아니라 유사도 보조점수
- Corr 히트맵: 예측변수가 아니라 독립변수 간 관계를 확인하는 EDA
