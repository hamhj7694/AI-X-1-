# 보이스피싱 빅데이터 분석을 위한 데이터셋 구축 방향

## Summary

이 프로젝트의 권장 주제는 **금융감독원 보이스피싱 사례와 정상 금융 콜센터 상담을 활용한 보이스피싱 유형·언어 특성 분석 및 텍스트 기반 탐지 가능성 검토**이다.

지금까지 확보한 보이스피싱 전사 결과는 원본 음성에서 자동으로 만든 데이터이므로 사람 정답이 확정된 골드 데이터가 아니라 **자동 전사·자동 역할 분류가 포함된 실버 데이터**이다. 따라서 이를 곧바로 범인·피해자 역할 분류의 정답이나 심리 상태의 정답으로 사용해서는 안 된다. 반면 사건 유형 분류, 단어·표현 분석, 유사 사건 군집화, 정상 금융상담과의 비교, 조기 탐지 가능성 탐색에는 충분히 활용할 수 있다.

가장 중요한 데이터셋은 다음 네 가지이다.

1. `vp_cases.csv`: 보이스피싱 사건 단위 핵심 데이터셋
2. `vp_utterances.csv`: 발화 단위 상세 데이터셋
3. `normal_finance_calls.csv`: 중복을 제거한 정상 금융 콜센터 상담 데이터셋
4. `detection_samples.csv`: 전체 대화와 통화 내 임의 구간의 탐지를 함께 수행하는 데이터셋

여기에 경찰 통계 `df_police.csv`와 우체국 피해사례 `df_postal.csv`는 개별 통화와 직접 결합하지 않고, **연도·사기유형·사칭기관 수준의 외부 설명 자료**로 사용한다.

머신러닝 수업 과제의 핵심 분석은 아래 세 가지로 구성하는 것이 적절하다.

- 정상 금융상담과 보이스피싱 대화의 이진 분류
- 대출사기형과 수사기관 사칭형의 유형 분류 및 중요 단어 해석
- 라벨에 의존하지 않는 유사 사건 군집화

향후 서비스인 신뢰인·사칭기관·은행 담당자 알림은 데이터 분석 결과를 활용하는 **서비스 확장안**으로 제시한다. 현재 데이터로는 알림이나 송금 공동승인이 실제 피해를 얼마나 줄이는지 검증할 수 없으므로, 이번 과제에서는 `보이스피싱 탐지 → 사칭 대상·위험 행동 추출 → 개입 경로 제안`까지만 다룬다.

## 1. 문서 목적

이 문서는 현재 보유한 자료를 어떤 관계로 묶고, 어떤 분석용 데이터셋으로 변환해야 하는지를 결정하기 위한 설계 문서이다. 아직 실제 CSV를 생성하거나 머신러닝 모델을 학습하지 않는다.

최종 결과물은 다음 흐름을 목표로 한다.

```text
원본·공개 데이터
→ 분석 가능한 표 형태의 데이터셋 구축
→ 탐색적 데이터 분석
→ 머신러닝 분류·군집화
→ 대시보드 작성
→ 분석 인사이트와 서비스 확장안 제시
```

## 2. 현재 보유 데이터

### 2.1 금융감독원 보이스피싱 음성·영상

원본 출처는 금융감독원 게시물의 다음 세 범주이다.

- 그놈 목소리 - 대출사기형
- 그놈 목소리 - 수사기관형
- 바로 이 목소리

현재 자동 처리 결과의 전체 요약은 다음과 같다.

| 항목 | 수량 |
|---|---:|
| 입력 파일 | 402개 |
| 완료 파일 | 402개 |
| 누락 파일 | 0개 |
| 자동 분리 사건 후보 | 776건 |
| 전체 발화 | 32,831개 |
| 학습 후보 발화 | 26,811개 |
| 검수 필요 발화 | 6,020개 |
| 자동 역할 OFFENDER | 21,004개 |
| 자동 역할 VICTIM | 5,943개 |
| 자동 역할 REVIEW | 5,884개 |
| 빈 전사 파일 | 10개 |
| 화자 미분리 파일 | 0개 |

처리에는 다음 모델과 규칙이 사용되었다.

- 음성 전사: `mobiuslabsgmbh/faster-whisper-large-v3-turbo`
- 화자 분리: `pyannote/speaker-diarization-community-1`
- 사건 경계: 대화 간격과 문맥에 따른 자동 규칙
- 범인·피해자 역할: 발화 내용과 대화 패턴에 따른 자동 추정

따라서 다음 필드는 관측된 원자료가 아니라 자동 생성값이다.

```text
사건 경계
화자 구간
OFFENDER / VICTIM 역할
role_heuristic_score
검수 필요 여부
```

### 2.2 50개 검토 표본

기존 검수표에는 50개 파일, 약 83~85개 사건, 4,201개 발화가 포함되어 있다. 사건 수가 두 방식에서 다르게 집계될 수 있으므로 실제 데이터셋 생성 시 `file_id + case_id` 중복과 빈 사건을 다시 점검해야 한다.

이 표본에서는 발화의 약 24%가 3글자 이하였기 때문에 무작위 발화 검수 시 `네`, `예`, `아`와 같은 짧은 발화가 많이 선택되었다. 이는 내용 분석용 표본 추출을 발화 균등 무작위 방식으로 하면 정보량이 낮아질 수 있음을 보여준다.

### 2.3 정상 금융분야 고객상담 데이터

`00.금융분야 고객상담 데이터`는 AI-Hub의 2025년 금융분야 고객상담 데이터이다. 공식 설명상 하나은행·하나손해보험·하나증권에서 발생한 **실제 금융기관 콜센터 상담을 기반으로 구축한 텍스트 데이터**이다. 대면 상담 데이터가 아니며 원본 음성도 포함되어 있지 않다.

로컬 보유량은 다음과 같다.

| 분야 | 원천데이터 | 라벨링데이터 |
|---|---:|---:|
| 은행 | 30,158건 | 45,000건 |
| 보험 | 21,214건 | 27,000건 |
| 증권 | 13,890건 | 18,000건 |
| 합계 | 65,262건 | 90,000건 |

AI-Hub 최종 공개 설명은 원천 71,257건, 라벨 100,000건이므로 현재 로컬 자료는 최종판보다 적다. Beta 버전이거나 일부만 받은 자료일 가능성을 기록해야 한다.

라벨링데이터에는 같은 상담 `source_id`가 여러 QA 작업으로 반복된다. 동일 상담 본문이 최대 7~9회 나타날 수 있으므로 정상 통화 수를 90,000건으로 세면 안 된다.

정상 상담 비교용으로 사용할 부분은 아래뿐이다.

```text
source.source_id
source.consulting_content
source.source_date
source.source_institution
consulting.consulting_category
consulting.consulting_topic
```

다음 필드는 정상 대화 원문으로 사용하지 않는다.

```text
qa_data.instruction
qa_data.input
qa_data.output
consulting_summary
```

이 값들은 요약·Instruction Tuning을 위해 가공되거나 생성된 데이터이기 때문이다.

### 2.4 경찰 공개 통계

`df_police.csv`는 다음과 같은 집계형 데이터이다.

- 2016~2025년
- 기관사칭형·대출사기형
- 발생건수·피해자 수·피해액·검거인원
- 연도·성별·연령대 등 일부 분류축

이 데이터는 개별 보이스피싱 통화 ID가 없으므로 전사 사건과 직접 행 결합할 수 없다. 연도와 사기유형 수준의 사회적 배경과 추세를 설명하는 데 사용한다.

### 2.5 우체국 피해사례

`df_postal.csv`는 184건의 2025년 전화 보이스피싱 피해 관련 자료이며 다음 변수를 포함한다.

- 연령대
- 피해자 성별
- 최초 접수년·월
- 피해액
- 사기유형
- 사칭기관
- 피해구제 신청사유
- 접근매체

이 데이터도 전사 사건과 동일한 개별 사건이 아니므로 직접 병합하지 않는다. 피해 유형·사칭기관·피해액의 분포를 비교하는 보조 자료로 사용한다.

## 3. 과제의 권장 중심 주제

### 3.1 권장 제목

> 정상 금융상담과 보이스피싱 대화의 텍스트 기반 분류 및 유형별 언어 특성 분석

서비스 방향까지 제목에 포함하려면 다음처럼 표현할 수 있다.

> 정상 금융상담 대비 보이스피싱 조기 탐지와 사칭 대상·위험행동 기반 개입 경로 설계

### 3.2 핵심 연구 질문

1. 정상 금융상담과 보이스피싱 대화는 텍스트 특성만으로 구분할 수 있는가?
2. 대출사기형과 수사기관 사칭형을 구분하는 주요 단어와 표현은 무엇인가?
3. 기존 폴더 분류 외에 비지도학습으로 세부 사기 유형을 발견할 수 있는가?
4. 전체 대화뿐 아니라 통화의 초반·중반·후반 또는 임의 구간만으로도 정상·보이스피싱을 탐지할 수 있는가?
5. 보이스피싱 의심 대화에서 사칭 대상과 위험 행동을 추출할 수 있는가?
6. 경찰·우체국 데이터에서 확인되는 피해 특성과 대화 데이터의 유형 분포는 어떤 관계를 보이는가?

### 3.3 이번 과제에서 제외하거나 보조로 둘 내용

- 발화 주도권 종합점수
- 피해자의 실제 신뢰 정도
- 실제 범행 성공 여부
- 실제 송금 여부와 실제 피해액
- 신뢰인 개입에 따른 피해 감소 효과
- 음성만으로 범인의 실제 신원을 확인하는 기능

발화시간, 발화 수, 피해자 단답률 등은 기술통계로 남길 수 있지만 현재 자료에는 범인 단독 음원과 편집 영상이 포함되어 있어 `대화 주도권`으로 해석하지 않는다.

## 4. 권장 데이터셋 구조

하나의 거대한 CSV보다 목적이 다른 테이블을 ID로 연결하는 구조가 적합하다.

```text
vp_files
 └─ vp_cases
     ├─ vp_utterances
     ├─ detection_samples
     └─ intervention_features

normal_finance_calls
 └─ detection_samples에 정상 대화 표본 추가

df_police      외부 집계 통계
df_postal      외부 피해사례
```

### 4.1 `vp_files.csv`: 보이스피싱 원본 파일 테이블

한 행은 원본 MP3 또는 MP4 한 개이다.

| 변수 | 설명 | 성격 |
|---|---|---|
| `file_id` | 원본 파일 고유 ID | 관측값 |
| `source_category` | 원래 폴더 분류 | 출처 라벨 |
| `source_file` | 원본 파일명 | 관측값 |
| `publication_date` | 제목에서 추출한 게시일 | 파생값 |
| `media_type` | MP3/MP4 | 관측값 |
| `duration_sec` | 전체 재생시간 | 관측값 |
| `case_count` | 자동 분리 사건 수 | 자동값 |
| `turn_count` | 전체 발화 수 | 자동값 |
| `empty_transcript` | 빈 전사 여부 | 품질값 |
| `multi_case_file` | 다중 사건 포함 여부 | 자동값 |
| `media_composition` | 전체통화/범인단독/편집영상/불명 | 추론값 |

`publication_date`는 사건 발생일이 아니다. 파일명이나 게시물에서 확인된 날짜라면 `게시일`로만 저장한다.

### 4.2 `vp_cases.csv`: 보이스피싱 사건 단위 핵심 데이터셋

한 행은 자동으로 분리된 하나의 사건이다. 머신러닝과 대시보드의 중심 테이블이다.

### 식별·출처 변수

```text
file_id
case_id
source_category
source_file
case_start_sec
case_end_sec
duration_sec
```

### 텍스트 변수

```text
full_text
offender_text
victim_text
normalized_full_text
normalized_offender_text
```

원본 텍스트는 항상 보존하고 분석용 정규화 텍스트를 별도로 만든다.

### 기본 통계 변수

```text
turn_count
speaker_count
offender_turn_count
victim_turn_count
unknown_turn_count
short_turn_count
short_turn_ratio
avg_turn_length
offender_text_length
victim_text_length
```

### 사건 유형 변수

```text
source_category
supervised_target
predicted_case_type
case_type_probability
cluster_id
```

각 변수의 의미를 분리한다.

- `source_category`: 원래 폴더명
- `supervised_target`: 지도학습에 사용할 정답
- `predicted_case_type`: 모델이 예측한 유형
- `cluster_id`: 비지도학습에서 생성된 군집

`바로 이 목소리`는 여러 유형이 섞인 공개 컬렉션이므로 세 번째 사기 유형으로 사용하지 않는다. 대출사기형·수사기관형으로 학습한 모델을 적용해 유형을 추정하거나 비지도 군집화 대상으로 사용한다.

### 사칭 대상 변수

```text
claimed_entity_type
claimed_entity_name
claimed_person_relation
claimed_job_title
```

`claimed_entity_type`의 권장 범주는 다음과 같다.

```text
PUBLIC_AGENCY
FINANCIAL_COMPANY
DELIVERY_COMPANY
FAMILY
ACQUAINTANCE
EMPLOYER
OTHER
UNKNOWN
```

### 위험 행동 변수

```text
transfer_request
cash_withdrawal_request
cash_delivery_request
atm_visit_request
bank_visit_request
app_install_request
remote_access_request
account_information_request
credential_request
id_copy_request
call_maintenance_request
outside_contact_restriction
mentioned_amount
```

### 설득·압박 표현 변수

```text
authority_count
fear_threat_count
urgency_count
secrecy_count
behavior_control_count
money_request_count
benefit_promise_count
information_request_count
```

이 변수들은 사람 정답이 아니라 키워드·규칙 또는 별도 NLP 모델로 생성한 탐색용 값이다. `feature_source=RULE` 또는 `feature_source=MODEL`을 함께 기록한다.

### 품질 변수

```text
asr_avg_logprob
role_heuristic_score_mean
unknown_role_ratio
empty_text_ratio
quality_flag
label_source
label_status
```

권장 라벨 상태는 다음과 같다.

```text
SILVER     자동 생성·미검수
REVIEWED   일부 사람이 확인
GOLD       명확한 기준으로 정답 확정
```

현재 대부분의 보이스피싱 데이터는 `SILVER`이다.

```text
quality_flag
```

활용 목적은 다음과 같다.

- 범인 추정 발화의 빈출 단어·n-gram 분석
- 질문·명령·금전 요구 표현 탐색
- 피해자의 의심·거절 표현 후보 탐색
- 유사 발화 군집화
- 사건 단위 파생변수 계산

`auto_role`은 정답 라벨이 아니므로 이를 목표값으로 한 범인·피해자 분류 정확도를 주장하지 않는다.

### 4.4 `normal_finance_calls.csv`: 정상 금융상담 비교 데이터셋

한 행은 하나의 고유 콜센터 상담이다.

```text
source_id
source_date
source_institution
consulting_category
consulting_topic
raw_text
normalized_text
turn_count
client_age_group
client_gender
dataset_split
```

구축 원칙은 다음과 같다.

1. `TL/VL`의 `source.consulting_content`에서 대화 본문을 가져온다.
2. `source_id` 기준으로 중복 상담을 한 건만 남긴다.
3. QA·모범답안·상담요약은 분류 입력에서 제외한다.
4. `TX/RX`는 제거하거나 양쪽 데이터에 공통인 중립 화자 태그로 바꾼다.
5. 보이스피싱과 비교할 때 우선 은행 상담만 사용한다.
6. 연령·성별은 보이스피싱 데이터에 같은 기준의 값이 없으므로 정상·사기 분류 모델 입력에서 제외한다.

### 우선 사용할 정상 상담 주제

```text
대출문의(만기/연장/조회등)
이자/연체금액
거래내역/잔액조회
중계요청/착오송금
자동이체조회
금융거래한도/비대면한도계좌
만기,연장/해지,수신
```

이 주제들은 보이스피싱과 같은 금융 용어를 사용하므로 단순한 영역 차이보다 실제 사기 표현의 차이를 학습하는 데 도움이 되는 `hard negative`이다.

보험·증권 상담은 2차 일반화 평가에 사용한다. 처음부터 모두 정상군에 넣으면 모델이 `자동차`, `보험료`, `주식`, `매도` 같은 분야 단어만으로 정상 여부를 구분할 수 있다.

### 4.5 `detection_samples.csv`: 전체·구간별 탐지 데이터셋

정상 금융상담과 보이스피싱 탐지에 사용하는 통합 실험 테이블이다. 한 통화의 전체 대화 표본과 통화 곳곳에서 추출한 부분 구간 표본을 함께 저장한다.

```text
conversation_id
source_group
fraud_label
sample_scope
window_start_turn
window_end_turn
window_size
window_position
relative_position
window_text
claimed_entity_seen
risky_action_seen
first_risky_action_turn
```

`sample_scope`는 다음처럼 구분한다.

```text
FULL      전체 대화 탐지
WINDOW    통화 내 부분 구간 탐지
```

권장 탐지 범위는 다음과 같다.

```text
전체 대화
초반 구간
중반 구간
후반 구간
일정 크기로 이동하는 슬라이딩 구간
```

부분 구간은 예를 들어 5개 또는 10개 발화를 하나의 묶음으로 정하고, 시작 위치를 옮기면서 생성한다.

```text
1~10번 발화
6~15번 발화
11~20번 발화
...
```

먼저 `sample_scope=FULL`로 전체 대화 기본 탐지 성능을 확인하고, 같은 모델 구조를 `WINDOW` 표본에 적용해 통화 위치에 따른 성능을 비교한다. 이를 통해 초반만 보는 조기 탐지뿐 아니라 **통화 어느 부분이 입력되더라도 탐지가 가능한지**를 확인할 수 있다.

부분 구간은 같은 통화에서 여러 개 생성되므로 반드시 `file_id` 또는 `source_id`로 학습·시험 데이터를 먼저 분리한 뒤 구간을 만들어야 한다. 그렇지 않으면 같은 통화의 다른 구간이 학습과 시험에 동시에 들어가는 데이터 누수가 발생한다.

### 4.6 `intervention_features.csv`: 서비스 확장용 데이터셋

한 행은 하나의 보이스피싱 의심 사건이며, 탐지 결과와 개입 정책을 연결한다.

```text
conversation_id
fraud_probability
claimed_entity_type
claimed_entity_name
requested_action
risk_level
recommended_contact
recommended_action
recommendation_rule_id
```

예시 규칙은 다음과 같다.

| 탐지 정보 | 추천 개입 |
|---|---|
| 가족·지인 사칭 | 신뢰인 및 실제 당사자 확인 |
| 검찰·경찰 사칭 | 신뢰인 + 공식 기관 확인 |
| 금융회사 사칭 | 신뢰인 + 실제 금융회사 담당자 |

| 인증정보 요구 | 인증수단 보호 + 금융회사 확인 |

`recommended_contact`와 `recommended_action`은 데이터에 존재하는 정답이 아니다. 분석자가 정의한 서비스 정책이므로 머신러닝 예측 정확도의 평가 대상으로 사용하지 않는다.

## 6. 머신러닝 분석 방향

### 6.1 분석 1: 정상 금융상담 대 보이스피싱 분류

### 질문

> 정상 금융상담과 보이스피싱 대화를 텍스트만으로 구분할 수 있는가?

### 목표값

```text
0 = LEGITIMATE_FINANCIAL_CALL
1 = VOICE_PHISHING
```

### 추천 모델

- TF-IDF + Logistic Regression
- TF-IDF + Linear SVM
- Naive Bayes 기준 모델
- 선택적으로 Random Forest 또는 XGBoost와 텍스트 파생변수 결합

한국어 자동 전사 오타에 대응하기 위해 단어 TF-IDF와 문자 3~5-gram TF-IDF를 비교한다.

### 평가 지표

- Precision
- Recall
- F1-score
- PR-AUC
- 혼동행렬
- 정상 상담 오탐률

정상 통화가 훨씬 많을 수 있으므로 Accuracy만으로 평가하지 않는다.

### 6.2 분석 2: 보이스피싱 유형 분류

### 질문

> 범인 추정 발화의 단어와 표현으로 대출사기형과 수사기관형을 구분할 수 있는가?

### 목표값

```text
LOAN_FRAUD
INSTITUTION_IMPERSONATION
```

`바로 이 목소리`는 학습 정답에서 제외하고 모델 적용 대상으로 사용한다.

### 확인할 결과

- 두 유형의 분류 성능
- 유형별 중요 단어와 n-gram
- 오분류 사건의 공통 특성
- 원본 폴더와 실제 대화 내용이 맞지 않는 사례
- `바로 이 목소리` 사건의 예측 유형 분포

### 6.3 분석 3: 유사 사건 군집화

### 질문

> 기존 폴더 분류 외에 실제 대화 내용에 기반한 세부 유형을 발견할 수 있는가?

### 분석 단위

사건별 `normalized_offender_text`를 우선 사용한다. 역할 품질이 낮은 사건은 `normalized_full_text` 결과와 비교한다.

### 추천 방법

- TF-IDF + K-Means
- 문장 임베딩 + K-Means
- 문장 임베딩 + UMAP + HDBSCAN
- BERTopic을 이용한 주제 후보 탐색

### 예상 가능한 군집

- 신용등급 조작형
- 기존 대출 상환 요구형
- 공증료·보증금 요구형
- 검찰 사건연루형
- 명의도용·대포통장형
- 안전계좌 송금형
- 앱 설치·원격제어형
- 현금 인출·전달형
- 통장 대여·취업빙자형
- 납치·협박형

군집명은 모델이 자동으로 정한 정답이 아니다. 대표 단어와 대표 사건을 읽고 분석자가 사후에 붙이는 설명이다.

### 6.4 분석 4: 전체·부분 구간 탐지

### 질문

> 전체 대화뿐 아니라 통화의 어느 부분을 보더라도 보이스피싱을 탐지할 수 있는가?

### 비교

```text
전체 대화 성능

중반 구간 성능
후반 구간 성능
임의 슬라이딩 구간 성능
```

### 핵심 지표

```text
window_detection_recall
false_positive_rate
detection_before_risky_action_rate
performance_by_window_position
```

핵심 결과는 전체 대화 성능과 부분 구간 성능의 차이, 구간 위치별 성능, 위험 행동이 없는 구간의 탐지 성능이다. 위험 표현이 포함된 구간만 잘 맞히는 모델인지도 별도로 확인한다.

## 7. `네`, `예` 같은 짧은 발화 처리

짧은 발화를 전체 데이터에서 삭제하지 않는다. 분석 목적에 따라 다르게 사용한다.

| 목적 | 처리 |
|---|---|
| 원본 보존 | 그대로 유지 |
| 사건 내용 분류 | 제거하거나 낮은 가중치 적용 |
| 사건 군집화 | 내용 단어가 없는 발화 제외 |
| 피해자 반응 분석 | `BACKCHANNEL`로 유지 |
| 발화 수·대화 구조 통계 | 유지 |

권장 필드는 다음과 같다.

```text
raw_text
normalized_text
content_text
is_short_turn
is_low_information
utterance_function
```

불용어는 `네`, `예`, `아`, `어`, `음`, `여보세요`, 일반적인 인사 표현부터 시작하되 원문에는 반영하지 않는다. TF-IDF의 `min_df`와 `max_df`도 함께 사용해 지나치게 흔한 단어의 영향력을 줄인다.

## 8. 정상 금융상담과 보이스피싱 비교 시 주의점

두 데이터는 수집·처리 방식이 다르다.

| 보이스피싱 | 정상 금융상담 |
|---|---|
| MP3/MP4에서 자동 전사 | 콜센터 상담을 정제한 텍스트 |
| ASR 오타와 누락 존재 | 상대적으로 정돈된 문장 |
| 자동 화자·역할 분리 | TX/RX 구분 |
| 여러 연도·기관·매체 | 하나금융 계열 2025년 |
| 편집영상·범인단독 음원 포함 | 콜센터 대화 |
| 발화 시간 정보 있음 | 발화별 시간 정보 없음 |

모델이 사기 여부 대신 데이터 출처를 학습하지 않도록 아래를 통일한다.

- `TX/RX`, `OFFENDER/VICTIM` 같은 노출된 역할 문자열 제거
- 기관 실명 마스킹 방식 통일
- `●`, `▲`, `OO`, `XX` 등의 마스킹 기호를 `[MASK]`로 통일
- 파일명·폴더명·게시물 제목을 모델 입력에서 제외
- 공백·문장부호·반복문자 정규화
- 상담 요약과 QA를 모델 입력에서 제외

성능이 높게 나오더라도 출처 누수 여부를 확인하기 위해 중요 단어와 오분류 사례를 반드시 살펴본다.

## 9. 데이터 분할과 누수 방지

### 보이스피싱

같은 원본 파일에 여러 사건이 들어 있으므로 `file_id`를 그룹으로 분할한다.

```text
동일 file_id의 모든 사건
→ 전부 Train 또는 전부 Test
```

### 정상 금융상담

라벨링데이터에 같은 상담이 여러 번 반복되므로 `source_id` 기준으로 중복 제거와 그룹 분할을 수행한다.

```text
동일 source_id의 모든 QA 레코드
→ 상담 본문 1개만 유지
```

### 금지할 방법

```text
발화 행 단위 무작위 분할
사건 행 단위 무작위 분할
TF-IDF를 전체 데이터에 먼저 fit
동일 상담의 여러 QA를 별도 정상 통화로 계산
```

- 사칭기관별 피해액
- 대화 데이터와 외부 데이터의 유형 분포 비교

서로 다른 사건을 직접 결합한 것처럼 표현하지 않고 `외부 통계 비교`임을 화면에 표시한다.

### 10.6 서비스 확장 화면

- 탐지된 사칭 대상 유형
- 탐지된 위험 행동
- 추천 개입 대상
- 위험 행동 이전 탐지 비율
- 서비스 처리 흐름 예시

```text
보이스피싱 의심
→ 사칭 대상·위험 행동 추출
→ 사용자 경고
→ 신뢰인 알림
→ 공식 기관 확인
→ 고위험 금융거래 추가 확인
```

이 화면은 실제 피해 감소 성과가 아니라 분석 결과를 활용한 서비스 설계안이다.

## 11. 도출 가능한 인사이트

### 데이터에서 직접 확인할 수 있는 인사이트

- 보이스피싱 유형별 주요 단어와 표현의 차이
- 사칭되는 기관과 직책의 분포
- 송금·현금·앱 설치·개인정보 요구의 출현 빈도
- 금전 요구 이전에 나타나는 언어적 신호
- 정상 금융상담과 보이스피싱의 구분에 기여한 단어
- 첫 몇 개 발화에서 확보되는 탐지 성능
- 기존 폴더 분류에 포함되지 않은 세부 사건 군집
- 전사 품질과 역할 미분류 비율이 분석 결과에 미치는 영향

### 외부 데이터와 함께 확인할 수 있는 인사이트

- 공식 통계상 기관사칭형·대출사기형의 연도별 변화
- 피해가 집중된 사기유형과 사칭기관
- 대화에서 자주 나타나는 유형과 피해 통계상 주요 유형의 공통점
- 피해액이 큰 유형에서 등장하는 위험 행동을 별도 연구할 필요성

### 서비스 제안으로만 제시할 내용

- 사칭 대상에 따른 공식 확인 채널 연결
- 사전 등록 신뢰인 알림
- 고위험 거래의 일시 지연
- 은행 금융범죄 담당자 확인
- 신뢰인의 한시적 공동승인

## 12. 주장할 수 있는 것과 없는 것

### 주장 가능

```text
정상 금융상담과 보이스피싱 텍스트의 분류 가능성을 실험하였다.
사기 유형을 구분하는 주요 단어와 표현을 분석하였다.
전체 대화와 통화 내 부분 구간의 탐지 성능을 비교하였다.
사칭 대상과 위험 행동을 추출하여 개입 경로를 설계하였다.
자동 전사 기반 실버 데이터의 활용 가능성과 한계를 제시하였다.
```

### 주장 불가

```text
자동 역할 분류가 사람 정답 수준으로 정확하다.
피해자가 실제로 범인을 신뢰하거나 순응하였다.
분석된 사건에서 실제 송금 또는 피해가 발생하였다.
신뢰인에게 송금 권한을 넘기면 피해가 감소한다.
제안 시스템이 실제 금융거래를 안전하게 차단한다.
음성 군집이 동일 범인의 신원을 증명한다.
```

## 결론

현재 보이스피싱 전사 자료는 완전한 정답 데이터는 아니지만, 사건 단위 실버 데이터셋으로 정리하면 머신러닝 기반 빅데이터 분석 과제에 충분히 활용할 수 있다. 가장 우선할 것은 `보이스피싱 사건 테이블`과 `중복을 제거한 정상 금융상담 테이블`이다.

그다음 정상·사기 분류, 사기 유형 분류, 군집화, 조기 탐지 분석을 수행하고 이를 대시보드로 연결한다. 신뢰인 또는 은행의 거래 개입은 현재 데이터로 효과를 검증하는 대상이 아니라, 탐지 결과에서 도출되는 향후 서비스 설계안으로 구분한다.
